# Iteration 03 — Manual Test Cases

These are the checks you run with your own hands before the suite in `04_test_automation.md` runs them forever and before `05_deployment_guide.md` releases the code to the trading host. The automated tests prove the counting against a journal they seeded themselves; these prove it against a journal the desk actually wrote — including the one already on the host, whose rows predate the classification columns and are the single most realistic input this slice has.

Nothing here is non-deterministic. This slice makes no model call, so every sentence, every count and every exit code below is exactly reproducible; a deviation is a defect, not variance.

## How to run these

Work in a scratch state directory, and give yourself a copy of a real journal to read — that is what makes MT-06 meaningful:

```bash
cd strike_desk
export STRIKE_DESK_OPENALGO_API_KEY='<the key from /apikey>'
export STRIKE_DESK_STATE_DIR="$PWD/.state-manual"
export STRIKE_DESK_TICK_INTERVAL_SECONDS=120
mkdir -p "$STRIKE_DESK_STATE_DIR"
uv sync
# a copy of the host's journal, written by the previous release
scp desk:/var/lib/strike-desk/strike_desk.db "$STRIKE_DESK_STATE_DIR/legacy.db"
```

Keep three terminals with that environment exported: one running `uv run strike-desk run`, one for CLI commands, and one on `sqlite3 "$STRIKE_DESK_STATE_DIR/strike_desk.db"`. Where a case needs a specific decision you cannot wait for, force it — stop OpenAlgo for a data-quality decline, unset the Anthropic key for a specialist-unavailable one — and put it back afterwards.

## The cases

| ID | Title | Preconditions | Steps | Expected result | Covers |
| --- | --- | --- | --- | --- | --- |
| **MT-01** | A tick writes a classified decision | Service running, market open, flat book | 1. `uv run strike-desk tick-now`. 2. `SELECT outcome, reason_code, reason_category, reason_disposition, length(reason_text) FROM decisions ORDER BY id DESC LIMIT 1;` | Exactly one new row. `reason_category` and `reason_disposition` are both populated and match the code — a specialist code reads `specialist`/`degraded`, a regime code reads `regime`/`routine`. `reason_text` is one line of at most 400 characters that names the decisive fact. | AC-1, AC-3 |
| **MT-02** | Different causes classify differently | Service running | 1. With a position open on the index, run one tick. 2. Stop OpenAlgo, run one tick, restart it. 3. Read both rows. | The first is `hold` / `position-open` / `book` / `routine` and its sentence names the open symbol. The second is `decline` / `data-quality` / `data` / `degraded` and its sentence ends "An unreadable book is never assumed flat." Two refusals, two distinct causes, no shared bucket. | AC-1 |
| **MT-03** | The analyst's sentence rides along, and is the only part ever cut | A tick that read a regime | 1. Find a row with `regime_label` set: `SELECT reason_text FROM decisions WHERE regime_label IS NOT NULL ORDER BY id DESC LIMIT 1;`. 2. Set `STRIKE_DESK_REASON_TEXT_MAX_CHARS=150`, restart, run one more tick, then restore 400 and restart. | The first sentence ends `Analyst: <the rationale>`. Under the 150-character cap the deterministic verdict is still complete and intact; only the rationale is shortened, ending in `...`, and the whole line is at most 150 characters. | AC-3 |
| **MT-04** | The day reads back as a page | At least half a dozen decisions today | 1. `uv run strike-desk declines`. 2. Check the arithmetic against `SELECT outcome, reason_code, count(*) FROM decisions WHERE trading_day = date('now','+5 hours','+30 minutes') GROUP BY 1,2;`. | The header gives the total with its split into declines, holds and entries; the by-reason table gives each code's count, share, outcome, `category/disposition` and one-line summary; the disposition and category blocks sum to the total; the first and last times are IST and bracket the session; the cost matches the day's decision rows; and the regime-label block counts only labels read inside ticks. Every number matches the SQL. | AC-4, AC-5 |
| **MT-05** | A window, a machine reading, and an empty day | Two or more journalled days | 1. `uv run strike-desk declines --since 5`. 2. `uv run strike-desk declines --json \| python -m json.tool`. 3. `uv run strike-desk declines --day <a holiday>`. | The window prints one line per day oldest-first plus aggregate blocks whose totals equal the sum of the per-day lines. The JSON carries the same totals and per-reason counts as the text and is stamped with the taxonomy version and digest. The holiday reports zero decisions, empty blocks, a clean health section, and exits 0. | AC-6 |
| **MT-06** | The real host journal migrates in place | The copied `legacy.db` | 1. `cp legacy.db strike_desk.db` in the scratch state dir. 2. `sqlite3 ... "PRAGMA table_info(decisions);"` — note the columns and the row count. 3. `uv run strike-desk declines --day <a day it holds>`. 4. Repeat step 2 and compare. 5. Run the same report a second time. | Before the command the two columns are absent; afterwards they are present and the row count is identical. Every legacy row is still classified by category and disposition in the report, and the health block counts them all as `unstamped rows` — the number equals the legacy row count. The second run prints byte-identical output. | AC-7, AC-9 |
| **MT-07** | The health block refuses to flatter the journal | The migrated scratch journal | 1. `sqlite3 ... "INSERT INTO decisions (tick_id,trace_id,created_at_utc,trading_day,index_symbol,\"trigger\",outcome,reason_code,reason_text,reason_category,book_state_json,prompt_set_version,model_version,token_cost_micros,latency_ms,trace_complete,schema_version) VALUES ('manual-1','0','2026-08-21 06:00:00.000000',date('now','+5 hours','+30 minutes'),'NIFTY','manual','decline','not-a-real-code','hand inserted','regime','{}','ps-x','none',0,1,1,3);"`. 2. `uv run strike-desk declines; echo "exit $?"`. 3. Insert a second row with a real code but `reason_category='system'`. 4. Repeat the report. | The unknown code is counted under `unknown`, named on the `unknown reason codes` line, counted as a defect, and the command exits 2. The mis-stamped row is counted under the category its code resolves to and adds one to `taxonomy drift`. Nothing is silently absorbed. | AC-8, AC-11 |
| **MT-08** | Both new spans are in the trace | One tick and one report | 1. Take the newest decision's `trace_id`. 2. `SELECT name, attributes_json FROM traces WHERE trace_id='<id>' AND name='tick.decide';`. 3. `SELECT attributes_json FROM traces WHERE name='report.declines' ORDER BY id DESC LIMIT 1;` | `tick.decide` carries `decision.reason_category` and `decision.reason_disposition` beside the outcome and code. The report span carries `report.taxonomy` (`dt-1+<digest>`), `report.days`, `report.total`, `report.defects` and `report.healthy`, so the act of taking a report is itself in the append-only record. | AC-10 |
| **MT-09** | A crashed tick surfaces as a defect | Service stopped | 1. Point `STRIKE_DESK_STATE_DIR` at a directory you can make read-only mid-run, or temporarily rename `read_book_state` in a scratch checkout to force a raise. 2. Run one tick. 3. `uv run strike-desk declines; echo "exit $?"`. 4. Undo the change. | The row is `decline` / `internal-error` / `system` / `defect` with the exception type in its sentence, the report counts one defect, and the command exits 2. A crash is visible in the day's page, not only in the log. | AC-1, AC-11 |
| **MT-10** | An unclassified code cannot ship | A scratch checkout | 1. Add `REASON_EXPERIMENT = "experiment"` to `graph.py`. 2. `uv run pytest tests/test_decline_taxonomy.py -q`. 3. Remove it, then delete one entry from `_ENTRIES` and rerun. 4. Restore both. | The first run fails `test_every_code_the_graph_can_emit_is_classified` naming `experiment`. The second fails `test_no_taxonomy_entry_is_orphaned` naming the deleted code. The guardrail binds in both directions. | AC-2 |
| **MT-11** | The taxonomy is a versioned artifact | A scratch checkout | 1. `uv run strike-desk status` and note the `taxonomy` line. 2. Change one word in any template. 3. `uv run pytest tests/test_decline_taxonomy.py -q`, then `uv run strike-desk status`. 4. Revert. | The suite fails on the frozen sentence for that code, naming the old and new text, and the digest in `status` has changed while the version has not. A wording change is impossible to make by accident and trivial to attribute. | AC-12 |
| **MT-12** | Bad arguments are refused before anything is read | Any state | 1. `uv run strike-desk declines --day 21-08-2026`. 2. `uv run strike-desk declines --since 0`. 3. `uv run strike-desk declines --day 2026-08-21 --since 3`. | Each exits 2 with a message naming what was wrong — a date that is not `YYYY-MM-DD`, a count below one, and two mutually exclusive options. No report is printed and no query runs. | AC-6 |

## Coverage

Every acceptance criterion in `01_use_case.md` is covered: AC-1 (MT-01, MT-02, MT-09), AC-2 (MT-10), AC-3 (MT-01, MT-03), AC-4 (MT-04), AC-5 (MT-04), AC-6 (MT-05, MT-12), AC-7 (MT-06), AC-8 (MT-07), AC-9 (MT-06), AC-10 (MT-08), AC-11 (MT-07, MT-09), AC-12 (MT-11).

After a full pass, restore the sentence cap, the tick interval and any source you edited, and delete the scratch state with `rm -rf "$STRIKE_DESK_STATE_DIR"` — MT-07 deliberately writes rows that are wrong, and an append-only journal cannot be cleaned up any other way.
