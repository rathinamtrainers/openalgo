# Iteration 02 — Manual Test Cases

These are the checks you run with your own hands before the suite in `04_test_automation.md` runs them forever and before `05_deployment_guide.md` puts the analyst on the trading host. The automated tests prove the loop behaves against a scripted model; these prove the *system* behaves — that a real MCP subprocess starts, that a real model calls real OpenAlgo tools against a live broker session, and that the guardrails hold when you break things on purpose.

## How to run these

Work in a scratch state directory so nothing here touches a deployed journal, and point the desk at a local OpenAlgo with a live broker session and downloaded master contracts:

```bash
cd strike_desk
export STRIKE_DESK_OPENALGO_API_KEY='<the key from /apikey>'
export STRIKE_DESK_ANTHROPIC_API_KEY='<an Anthropic key with credit>'
export STRIKE_DESK_MCP_PYTHON="$HOME/openalgo/.venv/bin/python"
export STRIKE_DESK_MCP_SERVER_SCRIPT="$HOME/openalgo/mcp/mcpserver.py"
export STRIKE_DESK_STATE_DIR="$PWD/.state-manual"
export STRIKE_DESK_TICK_INTERVAL_SECONDS=120
export STRIKE_DESK_LOG_LEVEL=DEBUG
rm -rf "$STRIKE_DESK_STATE_DIR"
uv sync
```

Keep three terminals with that environment exported: one for `uv run strike-desk run`, one for CLI commands, and one for `sqlite3 "$STRIKE_DESK_STATE_DIR/strike_desk.db"`.

Unlike iteration 01, part of this slice is non-deterministic. The label, the confidence and the wording of the rationale come from a model and will differ run to run — what must not differ is the *shape*: a label from the fixed set, a confidence in range, at least one evidence item, a status, and a reason code that follows from them. Where a case below names a label, treat it as the expected class of answer during that market condition and investigate only a persistent mismatch, not a single one. Every case involving a guardrail, a deadline, a schema or a secret is fully deterministic and a deviation there is a defect.

Reads cost money. A full pass of these cases is on the order of thirty model calls, which at Haiku prices is a few cents; the `strike-desk status` line tells you the running total after each case.

## The cases

| ID | Title | Preconditions | Steps | Expected result | Covers |
| --- | --- | --- | --- | --- | --- |
| **MT-01** | One live read, end to end | OpenAlgo up with a broker session; market open; empty state dir | 1. `uv run strike-desk regime`. 2. Read the printed block. | Exits 0. `status: ok`; a label from the five; a confidence between 0 and 1; one sentence naming the readings it used; at least one evidence line with a tool name, a field and a value; a non-zero cost; a trace id. | AC-1 |
| **MT-02** | The read is grounded in what it fetched | MT-01 passed | 1. `SELECT rationale, evidence_json FROM regime_reads ORDER BY id DESC LIMIT 1;`. 2. For each number in the rationale, find it in the `tool.output` attribute of that trace's `regime.tool_call` spans. | Every number in the rationale and in each evidence value appears in a captured tool output. Nothing is cited from a tool that was not called. | AC-2 |
| **MT-03** | Only six tools exist, and none of them trades | Service checkout available | 1. `uv run python -c "from strike_desk.mcp_toolbox import REGIME_TOOLS; print(REGIME_TOOLS)"`. 2. `SELECT DISTINCT json_extract(attributes_json,'$."tool.name"') FROM traces WHERE name='regime.tool_call';` | The whitelist prints exactly `get_quote`, `get_historical_data`, `get_trend_snapshot`, `get_momentum_snapshot`, `get_volatility_snapshot`, `get_expiry_dates`. Every tool ever called is one of those six; no order, position, funds, square-off or alert tool appears. | AC-3 |
| **MT-04** | Missing tools fail the session closed | Service stopped | 1. Copy `mcpserver.py` to a scratch file and delete the `get_volatility_snapshot` tool from the copy. 2. Point `STRIKE_DESK_MCP_SERVER_SCRIPT` at the copy. 3. `uv run strike-desk regime`. 4. Restore the original path. | Exits non-zero with `MCP server is missing required tools: get_volatility_snapshot`. No read row is written; the desk refuses to run with a partial tool set rather than silently degrading. | AC-3 |
| **MT-05** | Every read lands in the journal, and the journal will not be edited | At least one read exists | 1. `SELECT count(*) FROM regime_reads;` before and after `uv run strike-desk regime`. 2. `sqlite3 ... "UPDATE regime_reads SET label='trending';"` then `"DELETE FROM regime_reads;"`. | The count increases by exactly one, and the new row has `source='cli'`, a populated `tick_id`, `trace_id`, `prompt_*` and `latency_ms`. Both write statements fail with `Error: regime_reads is append-only`, and the count is unchanged. | AC-4 |
| **MT-06** | A tick consults the analyst and scores its label | Market open; flat book; service running | 1. `uv run strike-desk tick-now`. 2. `uv run strike-desk journal`. 3. Join the tick's `regime_reads` row on `tick_id`. | Exactly one new decision row, outcome `decline`, reason one of `regime-not-tradeable`, `regime-low-confidence` or `specialist-unavailable`, its sentence ending with `Analyst: <the rationale>` when a label was read. `regime_label`, `regime_confidence`, `model_version=claude-haiku-4-5` and a non-zero `token_cost_micros` are all populated. No row ever shows outcome `enter`. | AC-5, AC-10 |
| **MT-07** | Confidence floor is enforced | Service stopped | 1. Set `STRIKE_DESK_MIN_REGIME_CONFIDENCE=0.99`. 2. Run ticks until a read returns `trending` or `range-bound`. 3. Restore the floor to 0.55. | Any tradeable label under 0.99 records `decline` / `regime-low-confidence` naming both the observed confidence and the floor. | AC-5 |
| **MT-08** | No usable market read declines on data quality | Service stopped | 1. Point `STRIKE_DESK_OPENALGO_BASE_URL` at a port with nothing listening (the MCP server starts fine; its tool calls fail). 2. `uv run strike-desk regime`, then run one tick. | The read is stored with `status='degraded'`, `label='unknown'`, a defect naming the failed calls, and `tool_error_count` equal to `tool_call_count`. The tick records `decline` / `data-quality`. Nothing is classified from data that was never read. | AC-6 |
| **MT-09** | An event window short-circuits the read | Service stopped | 1. Write `$STRIKE_DESK_STATE_DIR/events.json` with one window spanning the next hour, named `manual test window`. 2. `uv run strike-desk regime`. 3. Corrupt the file (`echo 'not json' > events.json`) and repeat. 4. Delete the file. | First run: `event-driven` at confidence 1.0, evidence citing `event-calendar`, `tool calls: 0`, cost `$0.0000`, and the row shows `model_calls=0` with `model_version='none'`. Second run: `status: degraded` with a defect naming the calendar, and the tick declines with `data-quality`. | AC-7 |
| **MT-10** | The analyst polices its own deadline | Service stopped | 1. Set `STRIKE_DESK_SPECIALIST_TIMEOUT_SECONDS=6` and `STRIKE_DESK_REGIME_DEADLINE_MARGIN_SECONDS=4` (a 2-second analyst budget). 2. Run three ticks in a row during market hours. 3. Restore both settings and run one more tick. | Each of the three records `decline` / `specialist-timeout` — not `specialist-unavailable` — within roughly two seconds. The fourth tick, after restoring the settings, completes normally, which proves the two-thread specialist pool was never starved by the abandoned reads. | AC-8 |
| **MT-11** | Every read leaves a connected, replayable trace | One completed read | 1. Take the newest `trace_id` from `regime_reads`. 2. `SELECT name, parent_span_id, duration_ms FROM traces WHERE trace_id='<id>' ORDER BY started_at_utc;` 3. Inspect one `regime.tool_call` row's `attributes_json`. | The trace holds the tick root (or `strike_desk.regime_cli`), one `regime.read`, one `regime.model_call` per round with `model.input_tokens` and `model.output_tokens`, and one `regime.tool_call` per call carrying `tool.name`, `tool.args`, `tool.ok`, `tool.latency_ms` and the captured `tool.output`. Every child's parent resolves inside the same trace. | AC-9 |
| **MT-12** | Cost and prompt stamps are real | Several reads exist | 1. `SELECT input_tokens, output_tokens, token_cost_micros, prompt_name, prompt_version, prompt_digest, prompt_set_version FROM regime_reads ORDER BY id DESC LIMIT 3;`. 2. Recompute: `input_tokens × 1 + output_tokens × 5`. 3. Edit one word of `prompts/regime_analyst.md`, run one more read, then revert. | The recomputed figure equals `token_cost_micros` exactly. Every row names the artifact and its digest. After the prompt edit both `prompt_digest` and `prompt_set_version` change; earlier rows keep the old values, so a change is attributable to a specific artifact. | AC-10 |
| **MT-13** | Neither key reaches the journal, the trace or the log | Several reads exist, including a failed one | 1. `sqlite3 ... .dump \| grep -c "$STRIKE_DESK_ANTHROPIC_API_KEY"`. 2. Repeat for the OpenAlgo key. 3. Grep the captured service log for both. 4. `ps -ef \| grep mcpserver` while the service runs. | The first three greps return zero. The fourth does show the OpenAlgo key in the MCP server's command line, which is that server's published interface and is the known limitation recorded in the implementation guide — confirm it appears nowhere else. | AC-11 |
| **MT-14** | Label stability on one snapshot | Market open and quiet (mid-session, no news) | 1. Run `uv run strike-desk regime` three times within two minutes. 2. Compare the three labels. | All three labels match. Confidences may differ in the second decimal and the wording may vary; a differing label across a two-minute window on a quiet market is a prompt defect to investigate, not variance to accept. | AC-12 |
| **MT-15** | Rounds and truncation are bounded | Service stopped | 1. Set `STRIKE_DESK_REGIME_MAX_ROUNDS=2` and `STRIKE_DESK_REGIME_TOOL_OUTPUT_CHARS=1000`. 2. Run one read. 3. Restore both. | `model_calls` is at most 2, and the read still ends with a submission because the final round forces one. At least one `regime.tool_call` span shows `tool.truncated=true` with `tool.output_chars` at the cap, and the captured output ends with the truncation marker. | AC-13 |
| **MT-16** | The desk survives the reasoning plane going dark | Service running and reading normally | 1. Unset `STRIKE_DESK_ANTHROPIC_API_KEY` and restart the service; let one tick run. 2. Restore the key and restart. 3. With the service running, `pkill -f mcpserver.py`; let two ticks run. | With no key, the startup log warns that the desk will decline, `roles=()`, and each tick records `decline` / `specialist-unavailable`. With the MCP server killed, the next read logs the session ending and restarts it; if the restart succeeds the read completes, and if it does not the tick declines with `specialist-unavailable`. In no case does the service crash, and in no case is a decision other than a decline produced. | AC-5, AC-6 |

## Coverage

Every acceptance criterion in `01_use_case.md` is covered: AC-1 (MT-01), AC-2 (MT-02), AC-3 (MT-03, MT-04), AC-4 (MT-05), AC-5 (MT-06, MT-07, MT-16), AC-6 (MT-08, MT-16), AC-7 (MT-09), AC-8 (MT-10), AC-9 (MT-11), AC-10 (MT-06, MT-12), AC-11 (MT-13), AC-12 (MT-14), AC-13 (MT-15).

After a full pass, restore every setting you changed — the confidence floor, the timeout pair, the round cap, the output cap and both MCP paths — delete `events.json`, and clear the scratch state with `rm -rf "$STRIKE_DESK_STATE_DIR"` so no test journal is ever mistaken for a real one.
